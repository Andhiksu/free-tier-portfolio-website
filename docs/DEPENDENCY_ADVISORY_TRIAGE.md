## Classification key

- `D/P`: direct production dependency.
- `T/P`: transitive dependency classified as production by the package manager. Sanity CLI
  packages often appear here even though they are not shipped in the static website.
- `T/D`: transitive development dependency.
- `T/M`: mixed development/build and Studio production-classified paths.
- **Runtime-relevant** means code can be present in a browser/authoring runtime; it does not mean
  the exploit preconditions are satisfied.
- **Tooling-only** means the package is limited to lint, build, language-server, or CLI execution.
- **Unreachable now** means the vulnerable operation has no attacker-controlled input or required
  feature in the current architecture. It is still a supply-chain finding.
- Upgrade type and breaking risk refer to the affected package version. A parent Astro or Sanity
  update may carry a different compatibility risk and requires a separate owner-approved change.

## Posture and recommended action

- **Runtime-relevant:** Astro is the only direct affected package in the public web manifest, but
  its vulnerable View Transition feature is absent. DOMPurify can exist in the authenticated Studio
  browser runtime, but the vulnerable hook pattern is absent. Nano ID and UUID are runtime-class
  transitive libraries whose vulnerable call signatures are not used by project code.
- **Tooling-only:** the remaining findings are confined to lint, type/language tooling, static
  builds, or Sanity CLI operations. They are not delivered as a Node production server because the
  public website is static.
- **Unreachable based on current architecture:** the direct Astro exploit and the affected Nano ID
  and UUID call signatures are absent. The public site also executes no Node or Studio CLI runtime.
  Other tooling advisories remain conditionally reachable if an operator processes crafted input or
  a hostile upstream response, so they are not globally classified as unreachable.
- **Requires owner-approved upgrade:** remediation should be a separate bounded dependency milestone:
  first patch direct Astro, then update/test the Sanity toolchain, then refresh remaining transitive
  build/lint resolutions under the frozen install and full browser/Studio checks.
- **Eligible for explicit risk acceptance:** tooling-only and currently unreachable entries may be
  accepted temporarily with an owner, expiry/review trigger, architecture constraints, and a ban on
  introducing untrusted YAML/TOML/CSS/SVG/archive inputs before remediation. Runtime-class XSS
  findings should receive the shortest acceptance window.

This matrix does not authorize an upgrade, override, lockfile refresh, install, audit fix, push,
pull request, merge, or deployment.
